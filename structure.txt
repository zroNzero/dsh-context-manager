==================== CostKillerOrchestrator 架构设计 ====================

一、设计哲学
驻留在 DSH 宿主进程中的单体插件，通过拦截 Agent Loop 并重写上下文，实现端到端算力截流。内部调度完全依赖本地确定性数据结构与查表规则，严禁调用大模型做路由或压缩决策。

二、核心数据结构 (ContextEnvelope)
- meta: { sessionId, turnId, targetModel, timestamp }
- zones: { static_zone, dynamic_zone, live_zone } // 分别存放不可变系统词、可压缩内容、不可侵犯的约束
- cacheState: { lastPrefixHash, isCacheSafe, ttlRemainingMs }
- budget: { maxInputTokens, maxOutputTokens, currentEstimatedCost }
- ledger: { originalTokens, compressedTokens, savedBySchema, savedByCompression, savedByCache, recallPenalty }

三、五大模块流转
1. AdmissionModule（准入指针化）：超大输出/日志落盘，只留收据与指针。
2. ExtractionModule（多引擎萃取）：并行竞标。AST处理代码骨架，TOON处理JSON。优先分节压缩，通用改写降级。
3. MemoryModule（计划感知折叠）：基于DAG结构化逐出。历史废案折叠为单行摘要。已压缩内容严禁二次修改。
4. CacheAnchorModule（缓存锚定仲裁）：计算净收益门控。破坏前缀且收益低于冷读代价直接否决。
5. RoutingModule（路由分发）：纯逻辑/短任务走本地Ollama，复杂任务走云端。

四、钩子拦截 (Hooks)
- Pre-Step Hook: 运行 Admission, Extraction, Memory, CacheAnchor。
- Routing Hook: 执行本地与云端路由。
- Pre/Post-Decode Hook: 输出阶梯截断，强制JSON/代码块，闭合即STOP。
- Immune Hook: 触发Fail-Closed、规则行为探针，更新实时算账 CostLedger。
